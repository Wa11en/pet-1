## Текст раскрытия стороннего платежа

Ниже текст для полей о механизме оплаты **после фактического подключения** и проверки. В текущем черновике указать отдельно, что реальная оплата ещё недоступна; не представлять её работающей.

> Установка бесплатна. Pro стоит 99 ₽ за один календарный месяц и отключает рекламу, открывает локальную статистику настроения, тегов и регулярности. Пользователь отдельно инициирует каждый платёж через СБП в форме YooKassa. Наш HTTPS-сервер создаёт и проверяет платёж, затем выдаёт подписанный доступ. Оплата проводится напрямую продавцу, независимо от платёжных инструментов магазина. BillingClient SDK/Pay SDK RuStore не используются. Автопродления, регулярных списаний и сохранения платёжного средства для них нет. Внешний браузер/банковское приложение используются для подтверждения СБП. До оплаты показываются цена, правило календарного срока, продавец, условия, возвраты, политика и контакты. Базовый дневник остаётся бесплатным и работает офлайн. Записи, поисковые запросы, настроение и теги в платёжный запрос не входят.

В предназначенные для них поля внести **реальные** домен backend, продавца, ссылки и PSP. Не помещать секрет YooKassa, закрытый ключ, recovery-код или тестовые ключи. Сторонняя платёжная форма не освобождает от декларации §9.1.

## Какие данные обрабатываются

Вопрос «обрабатывает ли приложение данные?» и вопрос «передаёт ли их с устройства?» различаются. Неверно писать «данных нет» для всей `store`-версии. В анкете пользоваться текущими названиями категорий; ниже — соответствия официальной справке, а не замена всех её вопросов.

| Категория / данные | Где, зачем, кому передаются | Как пояснить в анкете |
| --- | --- | --- |
| «Другой пользовательский контент»: текст, даты, настроение, теги, избранное, черновики, корзина | Локальная зашифрованная БД; ведение дневника. Не включаются в запросы рекламы/оплаты и не отправляются разработчику | Обработка на устройстве — да. Сбор сервером разработчика/передача рекламному или платёжному сервису — нет. Пользователь может сам экспортировать файл |
| Поисковые запросы, векторы/индекс, результаты, локальная статистика | На устройстве, встроенная модель; облачного анализа/обучения нет. История запросов не сохраняется | Локальная функция, без передачи; не декларировать вымышленную внешнюю AI-службу |
| «Файлы и документы»: выбранные TXT/MD, Markdown ZIP, `.pdiary` | Системный файловый выбор, только действие пользователя. Выбранный провайдер может быть облачным | Нет доступа ко всем файлам. Экспорт Markdown открыт, `.pdiary` защищён паролем. Не обещать, что пользовательский облачный провайдер никогда не передаёт файл |
| «ID пользователей» / «Идентификаторы»: UUID установки, ID заказа/запроса, хеш восстановления | HTTPS-сервер продавца для покупки, привязки и восстановления Pro. Исходный код поступает по HTTPS, в БД хранится SHA-256. ID платежа/заказа связан с PSP | Это псевдонимные данные, а не доказанная анонимизация. Для бесплатного дневника такие сетевые действия не обязательны |
| «История покупок»: сумма/валюта, дата, статус, ID/URL платежа, срок доступа, возврат | Сервер продавца и YooKassa для исполнения покупки, подтверждения, поддержки и учёта | Передача при оплате/проверке/восстановлении. В шаблоне сервера нет имени, email, телефона или банковских реквизитов клиента |
| Финансовые/банковские данные СБП | В форме YooKassa/банке по их правилам; дневник не вводит и не хранит реквизиты | Описать внешнюю платёжную цепочку. Не писать «никаких платёжных данных» только потому, что в APK нет реквизитов |
| «Идентификаторы», технические данные устройства/приложения/ОС/соединения, IP | Яндекс и зависимости SDK для загрузки/показа рекламы после отдельного действия | Учесть как передачу третьим лицам. `AD_ID` удалён, но могут быть другие технические ID; окончательный состав проверить по SDK/договору/сетевому тесту |
| Приблизительный регион | Может определяться рекламным сервисом по IP; GPS не запрашивается | Указать косвенное определение региона, если соответствующая категория спрашивается. Отсутствие GPS не доказывает отсутствие приблизительной географии |
| «Взаимодействие с приложением», «Диагностика» | Только технические события рекламы: загрузка, показы, ошибки, взаимодействие с объявлением; зависимости включают AppMetrica | Не называть это отсутствием всей аналитики. Аналитики действий с дневником и отправки его crash-report разработчику нет; настройки App Ad Analytics отключены |
| IP/служебные данные обращения к серверу | Доступны инфраструктуре HTTPS. Лимитер в памяти использует посоленные хеши адресов и минутные окна ограничения частоты; это не гарантия удаления каждого хеша ровно через минуту | Проверить логи хостинга/proxy и указать фактические сроки; не обещать нулевые логи всей инфраструктуры |
| Email/текст/вложения поддержки | Только если пользователь сам пишет на gr1val@yandex.ru; у владельца и почтовых сервисов | Не обязательны для ведения дневника; цель — ответ на обращение. Установить срок хранения, не просить записи/секреты |
| Биометрия | Android выполняет локальную проверку; приложение получает результат, не шаблоны | Не заявлять сбор биометрических шаблонов разработчиком |

Не добавлять в SDK/payment metadata текст, ID записи, теги, настроение, векторы, поисковый запрос или секрет восстановления. На стороне PSP текущий код отправляет только сумму 99.00 RUB, СБП, описание услуги, return URL и `checkout_id`; UUID установки/хеш восстановления не добавляются в metadata YooKassa.

## Разрешения и компоненты

Ниже список из исходных манифестов и наблюдённого **storeDebug** merged manifest. Он помогает подготовить ответы, но не удостоверяет будущий релизный APK: перед отправкой извлечь разрешения из его манифеста и сравнить заново.

| Разрешение | Обоснование |
| --- | --- |
| `INTERNET` | Реклама после пояснения и явные действия покупки/проверки/восстановления. Обычное разрешение действует на весь пакет; его нельзя включить только на время рекламы |
| `ACCESS_NETWORK_STATE` | Техническое состояние подключения, зависимость рекламной интеграции; не доступ к записям |
| `USE_BIOMETRIC`, `USE_FINGERPRINT` | Необязательный локальный вход средствами Android; биометрические шаблоны приложение не получает |
| `POST_NOTIFICATIONS` | Необязательные напоминания; на применимых версиях запрос при включении. Общий текст без содержимого дневника |
| `RECEIVE_BOOT_COMPLETED` | Восстановление расписания локальных напоминаний после перезагрузки |
| `com.google.android.finsky.permission.BIND_GET_INSTALL_REFERRER_SERVICE` | Обнаружено в merged manifest транзитивных зависимостей; проверить необходимость/действительное использование в окончательном SDK. Не выдавать наличие разрешения за доказательство отправки истории установок |
| `ru.privatediary.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | Собственное `signature`-разрешение AndroidX для внутренних receiver; не доступ к персональным данным другого приложения |

В текущем `store` удалены `AD_ID`, AdServices ID/Topics/Attribution и queries. Не запрашиваются местоположение, камера, микрофон, контакты, доступ ко всем файлам. Системный picker не равен широкому доступу к хранилищу. В `offline` нет сетевого разрешения и рекламного SDK; его ответы нельзя переносить на `store`.

Реклама: **Yandex Mobile Ads SDK 8.6.0**, учесть транзитивные зависимости, включая AppMetrica; перечислить фактический состав/версии итоговой сборки. Автоинициализация и preload отключены; процесс `:ads` запускается после действия пользователя, завершается при закрытии/уходе в фон. Он имеет общий UID с приложением: это ограничение поведения, не отдельная криптографическая песочница. Отсутствие передаваемых записей проверять отдельно.

## Согласия, хранение и права

Показ политики на первом запуске и пояснение рекламы не являются автоматическим доказательством правового основания каждой операции. [Дополнение к политике](legal/PRIVACY_ADDENDUM.template.ru.md) оставляет блокирующими ФИО оператора, основания, получателей/хостинг, сроки серверных/почтовых данных, удаление, права и при необходимости отдельные согласия. [Проект пояснений](legal/CONSENT_DISCLOSURES.ru.md) требует сверки с интерфейсом.

Локальная корзина — 30 суток с фактической очисткой после разблокировки/во время работы; это **не срок хранения данных PSP/рекламы/платёжного сервера**. На сервере автоматическая очистка и панель запросов пользователя пока отсутствуют. Нужно определить сроки по целям/основаниям и реализовать исполнимую процедуру, включая резервные копии, а не вписать произвольные «30 дней».

Действующие документы и ссылки публикует владелец после заполнения [полей](legal/README.md). Незавершённые юридические шаблоны не прикладывать как утверждённые документы. Анкета готова к переносу только после [проверок](RELEASE_CHECKLIST.md).
