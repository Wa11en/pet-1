# Начните здесь

Подготовлены тексты карточки, графика, снимки интерфейса, справка и материалы для оформления выпуска. **Приложение ещё не опубликовано в RuStore.** Для выпуска остаются данные владельца, реальные подключения рекламы и оплаты, публичные документы и APK с вашим ключом подписи.

Ниже — пять групп действий. Технические инструкции можно передать разработчику; готовые тексты и изображения уже находятся в этом пакете.

## 1. Соберите черновик карточки в консоли RuStore

Установка приложения — **бесплатно, 0 ₽**. Будущий Pro — **99 ₽ за календарный месяц**, каждое продление оплачивается пользователем вручную через СБП в YooKassa, **без автосписаний и автоматического продления**. Основные функции дневника остаются бесплатными и работают офлайн.

Для будущего выпуска с подключёнными рекламой и оплатой используйте русский комплект:

| Поле или материал | Что взять |
| --- | --- |
| Название | [store/ru/name.txt](store/ru/name.txt) |
| Краткое описание | [store/ru/short-description.txt](store/ru/short-description.txt) |
| Полное описание | [store/ru/full-description.txt](store/ru/full-description.txt) |
| Что нового | [store/ru/release-notes.txt](store/ru/release-notes.txt) |
| Почта поддержки | `gr1val@yandex.ru` |

Содержимое `.txt` можно целиком скопировать в поле. Английские варианты находятся в [store/en/](store/en/), обложка — [feature-en.png](store/assets/feature-en.png). Справка для пользователей и шаблон ответа поддержки лежат рядом с описаниями.

Подробности выбора — в [store/README.md](store/README.md).

## 2. Укажите владельца и завершите публичные документы

В аккаунте RuStore и правовых документах нужны ваши настоящие данные самозанятого: ФИО, ИНН и обязательные реквизиты. Они пока не предоставлены. Название Private Diary — бренд приложения, оно не заменяет юридические данные продавца.

В [legal/](legal/README.md) подготовлены шаблоны условий Pro, возвратов, сведений для политики и ответов поддержки. Заполните их по своим данным и договорам, проверьте обещанные сроки и процедуры. Маркеры `[[OWNER:...]]` и заголовки «черновик» нельзя оставлять в опубликованных документах. Перечень мест для заполнения — в [OWNER_FIELDS.md](legal/OWNER_FIELDS.md).

Опубликуйте окончательные политику, условия Pro и порядок возвратов по доступным HTTPS-ссылкам без входа в аккаунт. Основа русской политики — [docs/privacy/store/index.html](../docs/privacy/store/index.html), английской — [en.html](../docs/privacy/store/en.html). Проверьте соответствие этих страниц сведениям владельца, провайдерам и итоговому приложению. Само наличие HTML в архиве не означает публикацию сайта.

Перед включением оплаты укажите в приложении продавца и ссылки на условия Pro и возвраты. Эти страницы должны открываться только по явному нажатию пользователя. Пока сведения и настройки не заполнены, покупка остаётся отключённой; ссылка на шаблон документа не заменяет готовые условия.

## 3. Подключите рекламу, СБП и чеки

Оформите собственный рекламный блок Яндекса и проверьте договор. Подключите YooKassa для своего статуса самозанятого, СБП и подтверждённый порядок выдачи чеков НПД. Разверните платёжный сервер на собственном HTTPS-адресе и настройте ключ проверки Pro. Сейчас рабочие подключения отсутствуют: текущий APK не принимает настоящую оплату и не показывает настоящую рекламу.

Точный порядок — в [RUSTORE.md](RUSTORE.md), инструкция сервера — в [backend/README.md](../backend/README.md). Доступность нужных услуг и сторонней оплаты в RuStore нужно подтвердить по реальным договорам и актуальным требованиям. Секреты YooKassa, закрытые ключи и пароли не помещают в APK, архив материалов или переписку.

Проверьте реальный сценарий: отказ от рекламы, отмена платежа, успешная СБП, чек, восстановление Pro и возврат. При отказе или отсутствии интернета дневник должен оставаться доступным. Оплата Pro и его восстановление не переносят записи; для записей используется собственная резервная копия.

## 4. Получите отдельный APK с вашим ключом подписи

**Проверочные APK из GitHub подписаны тестовым Android Debug-ключом. Не загружайте их в RuStore.** Неподписанный технический кандидат также не подходит для выпуска.

Создайте и сохраните свой релизный ключ по [SIGNING.md](SIGNING.md), затем передайте разработчику готовые публичные настройки рекламы, сервера и документов. В исходном проекте после настройки подписи выполняется:

```sh
bash scripts/build_release.sh store
```

Итоговый файл: `app/build/outputs/apk/store/release/app-store-release.apk`. Проверять и загружать нужно именно этот отдельный подписанный файл. Ключ и его защищённая резервная копия остаются у владельца: тот же ключ понадобится для обновлений. Пароли не нужно присылать в поддержку или чат.

Если переходите с тестовой установки и хотите сохранить записи, сначала сделайте доступную зашифрованную `.pdiary`-копию с известным паролем. Новый сертификат может потребовать переустановку, которая удаляет локальные данные. Сохраните нужные черновики и верните нужные записи из корзины до копирования.

## 5. Проверьте анкету и отправьте выпуск вручную

Заполните сведения о рекламе, платных функциях, сторонней оплате, данных и разрешениях по [DATA_DISCLOSURE.md](DATA_DISCLOSURE.md). Укажите бесплатную установку и ручную оплату Pro; отсутствие автосписаний не означает отсутствие платных функций. Категорию и возрастную анкету выберите по фактическому содержимому, рекламе и условиям провайдеров — официальная возрастная категория в пакете не назначена.

Сверьте конечный APK с [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md), технические результаты — с [VALIDATION.md](VALIDATION.md). Передайте проверяющему [REVIEWER.md](REVIEWER.md). Тесты проверочной версии не заменяют испытание итогового APK с настоящими подключениями на телефоне.

Когда сведения, документы, подключения и конечный файл проверены, отправьте приложение на модерацию из своего аккаунта RuStore. Этот архив не отправляет приложение и не включает рекламу или приём денег автоматически.
