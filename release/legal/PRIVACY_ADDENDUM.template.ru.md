# Дополнение к политике store — незаполненные сведения владельца

**ВНУТРЕННИЙ ЧЕРНОВИК, НЕ ОТДЕЛЬНАЯ ПУБЛИЧНАЯ ПОЛИТИКА.** Включить проверенные сведения в единую финальную политику, отразить её в APK и на публичном сайте. Основа описания поведения — `app/src/store/assets/privacy/policy.json` версии `store-1`; этот файл её не меняет и не утверждает. Дата финальной редакции: `[[OWNER:policy_effective_date]]`.

## Оператор и способы связи

Оператор данных, обрабатываемых продавцом для оплаты, предоставления Pro и поддержки: `[[OWNER:seller_full_name]]`, ИНН `[[OWNER:seller_inn]]`, применяет НПД. Обязательные реквизиты/адрес: `[[OWNER:seller_required_contacts]]`. Публичное имя — Private Diary. По вопросам данных и прав пользователя: **gr1val@yandex.ru**. Финальная политика: `[[OWNER:privacy_url]]`.

Локальные записи, черновики, корзина, поисковые векторы и статистика обрабатываются на устройстве. Приложение не передаёт их разработчику, платёжному серверу или в рекламные запросы. Серверного аккаунта дневника и облачной синхронизации нет. Пользователь может сам экспортировать файл через выбранного файлового провайдера; облачный провайдер обрабатывает такой файл по собственным правилам.

## Цели, данные и основания

| Цель | Данные и получатели | Основание — заполнить владельцу |
| --- | --- | --- |
| Создать, проверить и восстановить Pro | HTTPS-сервер продавца: UUID установки/запроса/заказа, тариф, платёжный ID/URL, сумма/валюта, статус, даты, срок, признак возврата, хеш секретного кода; код поступает по HTTPS, исходное значение в БД не сохраняется | `[[OWNER:legal_basis_payments_and_contract]]` |
| Провести СБП и подтвердить оплату | YooKassa/банк: банковские данные в их форме, сведения транзакции; сервер передаёт 99,00 RUB, СБП, описание услуги и checkout ID | `[[OWNER:legal_basis_psp_and_receipts]]` |
| Защитить платёжный API | IP и технические сведения доступны HTTPS-инфраструктуре; встроенный лимитер использует посоленные хеши адресов в RAM и минутные окна ограничения частоты; это не гарантирует удаление каждого хеша через минуту | `[[OWNER:legal_basis_security]]` |
| Показать рекламу по отдельному действию | Яндекс и зависимости SDK: IP, данные устройства/ОС/приложения/соединения, доступные технические ID, события рекламы; приблизительный регион может определяться по IP | `[[OWNER:legal_basis_ads_and_recipients]]` |
| Ответить на письмо | Адрес отправителя, текст и добровольные вложения у продавца и его почтового сервиса | `[[OWNER:legal_basis_support]]` |

UUID и хеш не делают платёжные сведения анонимными: они связаны с покупкой и могут позволять связать обращения/установки. Удалённый `AD_ID` не доказывает отсутствие иных ID рекламного SDK. Локальная биометрия даёт приложению результат проверки Android, а не биометрический шаблон.

Точные получатели и роль каждого, юридические наименования, договоры, действующие ссылки на их документы и фактические места обработки: `[[OWNER:recipient_legal_names_roles_locations]]`. Хостинг/домен продавца: `[[OWNER:backend_origin]]`, `[[OWNER:hosting_operator]]`, `[[OWNER:hosting_location]]`; дополнительные подрядчики: `[[OWNER:subprocessors]]`. Политика Яндекса: https://yandex.ru/legal/confidential/ . Документы YooKassa: https://yookassa.ru/ . Ссылки провайдеров не заменяют сведения оператора.

Оценка трансграничной передачи и применимые действия до начала обработки: `[[OWNER:cross_border_assessment]]`. Не утверждать, что все данные остаются в РФ, пока места обработки и цепочка получателей не проверены.

## Сроки хранения и удаление

| Категория | Фактический текущий режим | Что обязательно завершить до запуска |
| --- | --- | --- |
| Записи на устройстве | Пока пользователь хранит их; корзина 30×24 часа, физическая очистка после разблокировки/во время работы, копии пользователь удаляет отдельно | Сохранить точное описание из локальной политики; не обещать гарантированное стирание флеш-памяти |
| Серверные записи Pro, платёжные ID и хеш кода | SQLite; автоматическая очистка отсутствует | `[[OWNER:payment_retention]]`: сроки/критерии отдельно для действующего доступа, восстановления, возвратов, учёта и защиты от повторного начисления; затем внедрить процедуру |
| Логи HTTPS/хостинга и служебные события | Зависит от фактической конфигурации; README требует отключать чувствительные access/APM-логи | `[[OWNER:security_logs_retention]]`, перечень логов, доступы и проверка отсутствия секретов/платёжных URL |
| Резервные копии сервера | Развёртывание ещё не выполнено | `[[OWNER:backups_retention]]`, цикл удаления/ротации и порядок обработки запроса при восстановлении копии |
| Обращения поддержки | Будущая переписка в почте | `[[OWNER:support_retention]]`, критерии удаления писем и вложений |
| У Яндекса, YooKassa, банков и иных самостоятельных операторов | Их фактические правила и применимые обязанности | Указать проверенные сроки/критерии или ссылки и способы обращения; не приписывать им срок в 30 дней или месяц без основания |

Порядок удаления/обезличивания по истечении сроков, ответственный и журнал исполнения: `[[OWNER:deletion_process]]`. Нельзя просто удалить весь платёжный реестр, если это ломает восстановление, обязательный учёт или защиту от повторного начисления. Необходимость сохранения отдельных сведений должна иметь конкретное основание и срок.

## Обращения и права

Пользователь может обратиться на **gr1val@yandex.ru** по вопросам состава, оснований и сроков обработки, получения сведений, исправления неточностей, ограничения/прекращения обработки, удаления и отзыва согласия в случаях, когда оно используется, а также защиты своих прав предусмотренными законом способами. Исполнение зависит от применимых оснований и обязанностей хранения; при сохранении данных оператор объясняет основание, состав и срок.

Локальные записи пользователь исправляет/удаляет в приложении, корзину очищает отдельно; очистка данных Android удаляет локальное хранилище в обычном процессе Android. Разработчик не может прочитать, восстановить или удалить за пользователя его локальные записи через сервер. Удаление приложения не удаляет автоматически сведения у платёжного/рекламного сервиса.

Проверка прав на платёж и порядок ответа без запроса PIN, дневника или кода восстановления по обычной почте: `[[OWNER:privacy_request_process]]`. Обязательные сроки и обоснованные ограничения: `[[OWNER:privacy_request_deadlines]]`. Жалобы/обращения в уполномоченный орган и применимые способы защиты: `[[OWNER:privacy_rights_contact_and_appeal]]`.

## До публикации

Юридическое основание не определяется одной кнопкой «Продолжить». Прочтение политики при первом запуске, согласие на рекламу, заключение сделки и согласие на обработку данных — разные действия. Проверить необходимость отдельного, конкретного и доказуемого согласия, его форму, срок, отзыв и учёт версии. Если основание требует изменения интерфейса/сервера, выполнить его до включения production-платежей/рекламы.
