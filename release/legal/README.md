# Правовые материалы владельца — черновики, не для публикации

Подготовлено 22.11.2026 для бесплатной `store`-версии «Личный дневник» (`ru.privatediary`). Публичное имя — Private Diary, поддержка — **gr1val@yandex.ru**. Владелец сообщил статус самозанятого физического лица в РФ; ФИО, ИНН и договоры не предоставлены. Эти файлы не подтверждают соответствие законодательству и не являются действующей офертой или утверждённой политикой. Ни один шаблон не загружен в RuStore и не опубликован на сайте.

Все маркеры `[[OWNER:...]]` заполняет владелец на основании фактической настройки и своих договоров. Нельзя публиковать документ с маркерами, заголовком «черновик» или вымышленными реквизитами. `[[OWNER:...]]` — блокирующее поле, а не готовый ответ для консоли.

## Реестр полей владельца

| Поле | Что внести / чем подтвердить |
| --- | --- |
| `seller_full_name` | ФИО продавца и оператора данных; публичное имя Private Diary не заменяет ФИО |
| `seller_inn` | ИНН и подтверждённый статус НПД; не помещать паспорт/СНИЛС в публичные документы |
| `seller_required_contacts` | Обязательные для выбранной формы продажи реквизиты и адрес для юридически значимых обращений; объём определить по применимым требованиям и договору PSP |
| `terms_effective_date`, `policy_effective_date`, `document_versions` | Согласованные даты вступления и версии документов |
| `privacy_url`, `terms_url`, `refunds_url` | Реальные публичные HTTPS-страницы без входа; URL из release-config — пока только непроверенный адрес |
| `backend_origin`, `hosting_operator`, `hosting_location`, `subprocessors` | Рабочий HTTPS-сервер, наименование хостинга, фактические места обработки/хранения и привлекаемые лица |

| `payment_retention`, `security_logs_retention`, `backups_retention`, `support_retention`, `deletion_process` | Конкретные сроки/критерии, основания, ответственный и исполнимый порядок удаления, включая резервные копии |

| `support_response_target`, `privacy_request_process` | Реалистичный срок первого ответа и порядок обработки обращений, соответствующие обязательным срокам |

| `owner_approval` | Подтверждение владельцем финальных текстов и их соответствия реальному APK/серверу |

## Как довести документы до публикации

1. Заполнить реестр, проверить договоры и внедрить обещанные процедуры. Срок Pro в один месяц не является сроком хранения платёжных данных. В текущем сервере автоматической очистки платёжных данных нет.
2. Включить сведения из дополнения в **единую** политику `store`, согласовать её с текстом внутри APK и поведением приложения. Не выдавать отдельный незаполненный шаблон за публичную политику.
3. Проверить оферту и возвраты для статуса владельца и модели ручного цифрового доступа. Не добавлять безусловный запрет возврата или отказ от обязательных прав пользователя.
4. Опубликовать только заполненные финальные редакции, проверить доступность URL и ссылки до оплаты. Сохранить версии и доказательства показанных покупателю условий. Сейчас отдельные ссылки на оферту/возвраты в пользовательском интерфейсе и сохранение версии принятых условий необходимо проверить/доработать перед запуском: наличие этого каталога ничего не включает.
5. Подписать конечный APK ключом владельца и пройти [чек-лист](../RELEASE_CHECKLIST.md). Публикация в магазине в эту подготовку не входит.
