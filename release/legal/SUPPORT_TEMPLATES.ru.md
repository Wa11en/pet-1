# Шаблоны ответов поддержки и обработки запросов

Внутренний материал. Адрес поддержки: **gr1val@yandex.ru**. Поля `[[CASE:...]]` заполняются по проверенному обращению; поля `[[OWNER:...]]` требуют решения владельца до запуска. Не обещать непроверенный платёж, возврат, срок удаления или восстановление утраченного PIN. Не пересылать личные записи/платёжные документы в публичные issues.

## Первый ответ

> Здравствуйте! Мы получили обращение № `[[CASE:id]]` о `[[CASE:topic]]`.
>
> Для проверки достаточно описания проблемы, версии приложения, модели телефона и версии Android. Для платежа укажите дату/время с часовым поясом, сумму и доступный ID заказа/транзакции. Не присылайте текст дневника, PIN, пароль резервной копии, код восстановления Pro, банковские пароли или полные реквизиты счёта/карты.
>
> Следующий ответ планируем до `[[CASE:date_with_timezone]]` в пределах применимых сроков. Поддержка Private Diary — gr1val@yandex.ru.

## Списание есть, доступа нет

> Проверьте текущий платёж в разделе Pro при доступной сети. Возврат из банковской формы сам по себе не подтверждает активацию. До проверки не оплачивайте ещё раз. Мы сверим операцию `[[CASE:transaction_reference]]` с YooKassa и сообщим результат. Основные функции дневника доступны без Pro и без интернета.

Внутренне: не активировать доступ по скриншоту. Проверить ID, магазин-получатель, 99.00 RUB, СБП, статус, связь с заказом, повторное начисление/возврат. Не менять SQLite наугад; нужна защищённая процедура администрирования с аудитом.

## Подтверждён возврат

> По обращению № `[[CASE:id]]` возврат `[[CASE:amount]]` по платежу `[[CASE:payment_reference]]` подтверждён `[[CASE:confirmed_at]]`. Идентификатор возврата: `[[CASE:refund_reference]]`. Статус у провайдера: `[[CASE:verified_status]]`. Поступление средств зависит от банка и платёжного сервиса: `[[CASE:verified_timing]]`.
>
> Серверное начисление за этот платёж отозвано. Уже выданный офлайн-доступ технически может действовать до указанного в нём срока. Записи и бесплатные функции дневника сохраняются.

Ответ «возврат отправлен» допустим только после проверенной операции в YooKassa. Сообщение о приёме заявки не является подтверждением возврата.

## Обоснованный ответ по результату обращения

> По обращению № `[[CASE:id]]` проверены `[[CASE:checked_facts_without_secrets]]`. Решение: `[[CASE:decision]]`. Основания: `[[CASE:specific_reason_and_applicable_terms]]`. Следующие действия/способ оспорить решение: `[[CASE:next_steps]]`. Если сведения неверны, ответьте на это письмо. Обязательные права пользователя сохраняются.

Не использовать шаблон «цифровой товар возврату не подлежит». Частичный возврат в текущем backend отзывает весь месяц соответствующей операции: решение и выполнение должны учитывать это ограничение.

## Запрос о персональных данных / удалении

> Запрос № `[[CASE:id]]` получен `[[CASE:received_at]]`. Уточним, какие сведения затронуты: данные прямой оплаты Pro, переписка поддержки или локальные записи. Для проверки прав предложим минимальный безопасный способ: `[[CASE:verification_method]]`. Не отправляйте код восстановления Pro или содержимое дневника по обычной почте.
>
> По результатам проверки сообщим состав данных, основания/сроки хранения и выполненные действия в применимый срок `[[CASE:applicable_deadline]]`. Если часть сведений необходимо сохранить, укажем конкретное основание и срок. Удаление приложения само по себе не удаляет сведения о платежах у провайдера.

Закрытие запроса:

> Выполнено `[[CASE:action]]` в отношении `[[CASE:data_scope]]` на `[[CASE:completed_at]]`. Сохранено `[[CASE:retained_data_or_none]]`; основание/срок: `[[CASE:reason_and_deadline_or_not_applicable]]`. Порядок удаления из резервных копий: `[[CASE:backup_process]]`. Способ дальнейшего обращения: `[[CASE:appeal]]`.

Внутренне: следовать утверждённому `[[OWNER:privacy_request_process]]`; не просить паспорт «на всякий случай», не раскрывать данные чужого платежа, фиксировать только минимально необходимые сведения. Процедура и сроки ещё не установлены. Не отправлять шаблон как будто удаление уже произошло.

## Потерян PIN / пароль копии / код Pro

> PIN и пароль зашифрованной копии разработчик восстановить не может. Если PIN утрачен, записи можно восстановить только из заранее созданной `.pdiary`-копии с известным паролем после создания новой установки. Очистка данных удалит локальные записи; сначала проверьте наличие копии вне приложения.
>
> Код восстановления Pro относится только к платному доступу и не открывает дневник. В текущей версии нет автоматического восстановления Pro по email. Если код потерян, мы можем проверить обращение об оплате по установленному порядку, но не обещаем техническое восстановление без него.

Нужно определить срок хранения почты/вложений и правила удаления по [дополнению к политике](PRIVACY_ADDENDUM.template.ru.md). Текст письма не заменяет операционную процедуру.
