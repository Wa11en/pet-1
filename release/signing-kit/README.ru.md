# Личная подпись Private Diary 1.0.0 (11)

Этот комплект подписывает проверенный `storeRelease` APK приложения `ru.privatediary` вашим собственным ключом на вашем ПК. Исходный APK ещё не подписан: в RuStore нужен файл, который появится в `output` после успешной проверки. Подпись не публикует приложение и не подключает платежи или рекламу.

## На Windows

1. Скачайте комплект на свой ПК и распакуйте **весь ZIP** в обычную локальную папку. Не запускайте скрипт прямо из архива. Доверяйте источнику комплекта: записанные в нём SHA-256 выявляют повреждение файлов, но не заменяют проверку источника.
2. Установите **JDK 17 или новее**. Рекомендуется [официальный Eclipse Temurin 21 JDK для Windows](https://adoptium.net/temurin/releases/?version=21&os=windows&package=jdk). Выберите JDK, при установке включите **Add to PATH** и **JAVA_HOME**, затем заново откройте окно запуска. Нужны обе команды: `java` и `keytool`. Android Studio, Android SDK и сборка приложения для подписи не нужны.
3. Дважды щёлкните **`Sign-Windows.cmd`**. Он запускает лежащий рядом `sign-release.ps1` через Windows PowerShell без профиля. `ExecutionPolicy Bypass` действует только в этом процессе; системные настройки не меняются. Если Windows показывает блокировку загруженного файла, сначала проверьте источник и содержимое комплекта.
4. При первом запуске придумайте пароль от **12 печатных ASCII-символов**: латинские буквы, цифры, знаки, можно пробел. Введите его в скрытом запросе и повторите с тем же регистром. Кириллица и другие символы вне ASCII не допускаются, чтобы один ключ можно было использовать на разных ОС. На следующих запусках вводится пароль существующего ключа.
5. После сообщения **«ГОТОВО»** заберите **`output/Private-Diary-1.0.0-RuStore.apk`**. Рядом будет `Private-Diary-1.0.0-RuStore.apk.sha256`. **В RuStore загружайте только подписанный APK**, а не ZIP, исходный unsigned APK, ключ или пароль.

Пароль вводите только в скрытом запросе на своём ПК: не в чат, не в командную строку, не в файл настроек. Скрипт временно передаёт его `keytool` и `apksigner` через переменную окружения своего процесса и очищает её в `finally`. Он не сохраняет пароль и не меняет постоянные `HOME`, `USERPROFILE`, `JAVA_HOME` или `PATH`.

## На Linux или macOS

Нужны Bash (включая встроенный в macOS 3.2), Python 3 и JDK 17 или новее с `java` и `keytool`. Их установка не выполняется скриптом. JDK можно взять с [официального сайта Eclipse Temurin](https://adoptium.net/temurin/releases/?version=21&package=jdk), выбрав свою ОС и архитектуру. Распакуйте весь комплект, откройте терминал в его папке и выполните:

```sh
bash sign-release.sh
```

Запросы пароля скрыты. Правила пароля, имя итогового APK и проверки подписи те же. Приватная папка по умолчанию — `~/.private-diary-signing`. Не запускайте скрипт через `sudo`: ключ должен принадлежать вам.

## Ваш ключ и резервные копии

По умолчанию Windows сохраняет ключ **вне комплекта**, в личной папке:

```text
%USERPROFILE%\.private-diary-signing\private-diary-release.p12
%USERPROFILE%\.private-diary-signing\publickeyfingerprint.txt
```

Ключ — PKCS12, alias `private-diary-release`, RSA 3072 / SHA256withRSA, срок сертификата 10 000 дней. `CN=Private Diary` — название приложения, не юридическое имя владельца. Новая папка Windows получает доступ только текущего пользователя и SYSTEM. Для уже существующей папки и ключа скрипт проверяет владельца и разрешения: доступ разрешён только вашему пользователю, SYSTEM и администраторам. Общие разрешения существующих папок он не меняет; при слишком широком доступе выберите новую личную локальную папку и восстановите туда свою копию ключа. Ключ не добавляется в `output` или распространяемый ZIP, не отправляется в облачную сборку и никогда не перезаписывается скриптом.

**До публикации сделайте две офлайн-резервные копии обоих файлов** на отдельных носителях. Храните пароль отдельно от копий. Защищённый паролем `.p12` всё равно является секретом: не добавляйте его в Git, общую папку, чат, магазин приложений или синхронизируемое облако. Не удаляйте эту папку после загрузки APK: все обновления должны использовать прежний ключ. Для переноса на другой ПК восстановите оба файла в папку ключа и используйте прежний пароль.

`publickeyfingerprint.txt` содержит только публичные данные:

```text
applicationId=ru.privatediary
alias=private-diary-release
sha256=64_ШЕСТНАДЦАТЕРИЧНЫХ_СИМВОЛА_SHA256_СЕРТИФИКАТА
```

Если отпечаток есть, а `.p12` пропал, скрипт **остановится** и потребует восстановить копию. Он не создаст другой ключ для уже известной подписи. Если потеряны и ключ, и отпечаток, скрипт не может сам распознать потерю: восстановите резервную копию до повторного запуска. Утрата ключа или пароля может лишить возможности выпускать совместимые обновления.

Для другой локальной папки можно задать `DIARY_OWNER_KEY_DIRECTORY` **только в текущем процессе** перед запуском скрипта. Это необязательно; используйте абсолютный путь вне комплекта, Git и синхронизации. Сетевые пути, ссылки/junction и известные папки OneDrive не допускаются. Не задавайте эту переменную навсегда. Windows и `sign-release.sh` используют одинаковые имена ключа, alias и формат отпечатка; Linux/macOS по умолчанию используют `~/.private-diary-signing`.

## Проверки и повторный запуск

Перед запуском инструментов подписи проверяются поля `release-manifest.json`, имена файлов и SHA-256 исходного APK и `tools/apksigner.jar`. Скрипт принимает только комплект `ru.privatediary`, версия `1.0.0`, `versionCode=11`, `minSdk=26`. Значения манифеста не выполняются как команды. Файлы комплекта и ключа через ссылки/junction отклоняются. Не меняйте манифест, APK или JAR вручную.

После подписи проверяются схемы APK v2/v3 и совпадение SHA-256 сертификата с вашим ключом и сохранённым отпечатком. Подпись Android Debug отклоняется. Временный APK становится итоговым только после этих проверок. Если в `output` уже есть APK или его SHA-256, переместите прежние выходные файлы в другую папку и повторите запуск: прежний ключ сохранится. При ошибке прочитайте сообщение в окне; пароль и ключ никому не отправляйте.

## Если на телефоне уже стоит версия из GitHub

Версия с Android Debug и выпуск с вашим новым сертификатом не устанавливаются друг на друга как обычное обновление. **Сначала экспортируйте зашифрованную резервную копию дневника из приложения, сохраните её отдельно и убедитесь, что знаете пароль копии.** Только после этого при необходимости удаляйте старую версию, устанавливайте подписанный APK и восстанавливайте дневник. Удаление приложения удаляет его локальные данные; пароль резервной копии дневника и пароль ключа подписи — разные пароли. Скрипт сам не удаляет приложение и не подключается к телефону.
